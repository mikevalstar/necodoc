# Postgres with Drizzle

## Status

Accepted.

## Context

The app stores users, sessions and (soon) documents and their answers:
relational data where Postgres is the default choice. We want typed queries
without a heavy ORM runtime.

## Decision

- **Postgres 18.** For local dev, run it natively with Homebrew
  (`postgresql@18`, see the [README](../../README.md)). No Docker needed.
- **Drizzle ORM** with the `postgres` (postgres.js) driver and `snake_case`
  column casing ([db/index.ts](../../apps/api/src/db/index.ts)).
- The schema lives in [db/schema.ts](../../apps/api/src/db/schema.ts), which
  re-exports the generated auth tables
  ([ADR 0007](0007-better-auth-for-authentication.md)).
- **Migrations** are SQL files generated by `pnpm db:generate` into
  `apps/api/drizzle/`, committed, and applied with `pnpm db:migrate`
  ([drizzle.config.ts](../../apps/api/drizzle.config.ts)). No `push` against
  shared databases.

## Consequences

Every schema change comes with a reviewed migration file. Drizzle's types
follow the schema, so a column change breaks the queries that use it at
compile time.
